# 定義データ（読み込み検査、表の定義、試験用データ）

## 約束

- 調整する値は、定義データ（`clipping_point/data/` のJSON）に出す。読み込むときに、必ず読み込み検査を通す。
- 読み込み検査と重ね方は `cp_core/datadefs.py`（ファイルに触れない。受けるのは「相対の名 → 文」の辞書）。ファイルを読むのは `cp_app/data_files.py`（pyxel と js をimportしない）。`cp_core` に pathlib、io、os、`open` を足さない。
- ファイルの形は2通りで、表の定義が持つ。1ファイル1表（`<表>.json`。`{"<表>": [項目, …]}`）と、1ファイル1項目（`<表>/<id>.json`。ファイルの名と `id` が同じ）。
- 問題は、最初の1件で止めず、ファイルと場所を付けて、全部を `DataError` に並べる。並びは、いつも同じ順（集合を回した順に頼らない）。ほかの例外にしない。
- 型は `type(...) is` で見る。bool を整数や数として受けない。文字列の数字、`NaN`、無限大、重複した鍵を受けない。
- 置き場の下のファイルは、全部を、名を挙げて検査へ渡す。2つの形に当たらない名は「知らないファイル」の問題（黙って無視しない）。
- `_` で始まる鍵は、どの階でも注（検査の外。使う側へ渡さない）。根拠の薄い値は、同じファイルの頭の `_notes` に `仮の値：<根拠>。<合わせる時>` と書く。
- 参照は、全部の表を読んでから照らす。どこからも参照されていない定義は警告。
- 警告は、出荷するデータも、試験用データを重ねた結果も、0件にする。道具 check（重ねた組も）と run `--pack` が、問題に数える。
- 表示名の字数の上限（`NAME_MAX`。車名もコース名も14字）は、画面と一緒に変える。
- 試験用データは、リポジトリの根の `testpacks/<名>/` に、同じ相対の名で置く。`clipping_point/` の下に置かない（出荷物に入る）。頭の `_notes` に、試験用データであることと、出荷物に入らないことを書く。
- 重ね方：1ファイル1表は、`id` が同じ項目を差し替え、新しい `id` を末尾に足す。1ファイル1項目は、同じ名のファイルで差し替え、新しい名で足す。重ねた結果を、同じ読み込み検査に通す。頭の形が合わないファイルは、重ねない。
- 重ねる口は、デスクトップ版の環境変数 `CP_DATA_PACK=<名>`（1つだけ。`id` と同じ字で、43字まで）。ブラウザ版は読まない。置き場が無い、空、名の字が違う、は `ValueError`。
- 重ねている間、ふつうの保存の名前空間は `pack_<名>`（`GameData.save_namespace`）。アプリは、これを、設定を読む保存の口へ渡す。
- 起動時に、デスクトップ版もブラウザ版も、巡回の口でも、定義データを読む（`cp_app/app.py` の `main()`。保存先を選んだ後）。
- 読み込んだ定義（`GameData`）は、引くたびに、奥まで新しい複製を渡す。使う側は、起動時やレースの開始時に1度引いて持つ。毎tick引かない。

## 値を読む口

- 規則の部品（`Int`、`Num`、`Bool`、`Enum`、`Ident`、`Label`、`Ref`、`ListOf`、`Obj`、`Opt`）と、実物の表の定義：`datadefs.py` の `TABLES`
- 読み込み：`datadefs.load_game_data(sources, pack=None, tables=TABLES)`。アプリからは `data_files.load(env, js)`
- 読み込んだ定義：`GameData` の `counts()`、`ids(表)`、`entry(表, id)`、`warnings`、`pack`、`save_namespace`
- 問題の行の形：`cars.json:cars[0].name: …`、`tracks/test_loop.json:name: …`。試験用データの中は、頭に `testpacks/<名>/`
- 置き場と環境変数の名：`data_files.py` の `DATA_DIR`、`PACKS_ROOT`、`PACK_ENV`
- 結果に出す値（`data` の `tables`、`warnings`、`pack`、`namespace`）：`cp_app/app.py` の `data_report()`。`namespace` は、設定を読んだ保存の口から取る
- 道具が自分で数える件数と、結果の確かめ：`tools/data_reference.py`

## Xを足したらYも

- 表を足したら、`TABLES`、実物のファイル、`tests/test_datadefs.py` の `BROKEN`（その表の、知らない鍵と、鍵ごとの壊した場合）、`tools/verify.py` の `AREAS`（実物のファイルは、1つずつ並べる）に足す。
- 項目（鍵）を足したら、表の定義、実物のファイル、`BROKEN` に足す（足さないと、テストが落ちる）。試験用データの項目にも足す。
- `BROKEN` は、入れ子、並び、省ける項目の中の鍵も、鍵の道（`engine.idle_rpm`）ごとに1件。札は、並ぶはずの行の場所と照らされる。
- 走りに効く値を変えたら、データの版（`data_version`）を上げる（見張りは、段0 区切り9で足す）。
- 実物の `id` と表示名を変えたら、`tools/selftest_break.py` の、定義データを壊す件（文字を置き換える所）を確かめる。
- 試験用データを足したら、`python3 tools/check.py --only data` で、重ねて読めることを見る。
- 検査の決まりを足したら、`tools/selftest_break.py` に壊す件を足す。

## テストと道具

- テスト：`test_datadefs.py`（実物、壊した場合、規則の部品、作り物の表の定義、重ね方、複製、問題の順）、`test_data_files.py`（置き場を読む、試験用データの名、環境の辞書と js、実物の試験用データ、アプリの配線の守りのテスト）。
- 道具 `python3 tools/check.py --only data`：出荷するデータと、各試験用データを重ねた組（どの組も、警告を問題に数える）。節の関数のテストは `tests/test_check_tool.py`。
- 道具 `python3 tools/run.py [--pack 名]`：結果の `data` を、道具が自分で数えた件数と照らす。`--pack` は、重ねる口と、保存の名前空間の切り替えを通す（全体の検証の `run-pack`）。
- 道具 web-smoke の筋書き `probe`：ブラウザ版が、出荷物の中の定義データを読めていること。道具 export：出荷物の `data/` が、ソースの木と同じで、表の定義が求めるファイルがあること。

## 落とし穴

- 標準のJSONの読みは、重複した鍵を後勝ちで通し、`NaN` も通す。`1e999` は無限大になる。
- 段0の起動は、設定を書かない。保存の口へ名前空間を渡し忘れても、保存のファイルでは分からない（結果の `namespace` と、守りのテストで見る）。
- 実物の表の定義には、まだ参照が無い。参照と警告は、テストの中の作り物の表の定義で確かめる。
- 重複した鍵か、`NaN`・無限大のあるファイルは、JSONが読めないファイルと同じ扱い。項目を検査へ渡さず、並ぶのは、そのファイルの行だけ（ほかの問題は、直して回し直すと出る）。行は、ファイルと鍵の名までで、何番目の項目かは出ない。
- ブラウザ版は、展開された出荷物の中の `data/` を、モジュールの場所から引いて読む（段0 区切り8の実測）。作業ディレクトリに頼らない。
- `pyxel package` は、名が `.` で始まるファイルとディレクトリを、出荷物に入れない（実測）。道具 export が、一覧の食い違いで落とす。
