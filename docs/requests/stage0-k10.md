## やること

区切り9で入ったもの（使う口）：世界 `Sim`（`sim.car` の `x`、`z`、`heading`。`sim.track`。`sim.spec`）、コースの表 `Track`（`n`、`ds`、`length`、`sample(番号)`、`pose_at()`）、車の値 `CarSpec`、表示用の値 `PlaceholderView`（`tick`、`renders`、`frame`、`notice`、`car`）と `car_view()`、走る台本 `tools/input_script_drive.json`（900 tick）と、指紋の筋書き `drive_900`（走行の下限つき）、デスクトップ版とブラウザ版の、世界の要約の比べ方（`cp_core/sim.py` の `SUMMARY_FIELDS` と `summary_compare()`）。selftest-break は、時間に頼る件（コマンドに `web_smoke.py`、`verify.py`、`--realtime` がある件）を1件ずつ、ほかを同時に4件回す。

座標の決まりは、2つある。取り違えないこと。

| 何 | 座標 | 面の向き | Pyxelの3Dへ渡すとき |
| --- | --- | --- | --- |
| コース、地面、カメラの目と注視点、車の位置、判定用の柱 | ロジックの座標（+z は、+x の左） | 3つ組を、そのままベクトルとして、(b−a)×(c−a) が外向き | 変換の関数を通す（z を反転。メッシュは、頂点の順も入れ替える） |
| 車の模型、模型に付ける印 | 模型の座標（鼻先が +X、右が +Z、上が +Y、原点は接地中心。右手系） | (b−a)×(c−a) が外向き | そのまま（反転も、入れ替えも、しない）。車の根のノードの変換の下に置く |

### 1. コースのメッシュ用の数値（`clipping_point/cp_core/track.py`）

- コースの表から、塊の並びを作る口。Pyxelに触れない。返すのは、塊ごとの、コースに沿った範囲、中心（x, z）、半径、部品（路面、白線、芝、壁）ごとの、頂点（ロジックの座標の x, y, z）と、三角形（頂点の番号の3つ組）と、色の役割の名。
- 幅の向きの並びは、重ねない：左の壁、左の芝、左の白線（舗装の、外側0.2 m）、路面（4つに割る）、右の白線、右の芝、右の壁。高さは、路面、白線、芝が0、壁は0〜0.9 m（壁は、舗装の外の、壁の位置に立つ板。コースの側を向く面だけ）。
- 寸法（区切りの間隔、路面を割る数、白線の幅、壁の高さ、塊の長さ）は、コースの定義データの項目（`mesh`）に出す。`testpacks/extreme/` のコースにも足す。
- 1周の継ぎ目（最後の区切りと、最初の区切り）も、つなぐ。どの三角形も、塊のどれか1つに入る。塊の半径は、その塊の頂点を、全部含む。
- テスト（`tests/test_track.py`）：面の向き（細目の3番）。三角形の数（全周で、3,000〜4,000の間）。塊の数と、半径。継ぎ目。頂点が、路面は舗装の内、芝は舗装の端と壁の間、にあること（照会で引き直して確かめる）。同じ項目から、同じ数値。

### 2. カメラ（`clipping_point/cp_core/camera.py`）

- 後方追従：車の位置と向き（ロジックの座標）と、カメラの値（定義データの表 `cameras` の `chase`）から、目、注視点、画角、手前、奥を返す。
- 塊が見えるかの判定（距離が、奥＋半径より近く、前方への射影が、−半径より大きい）と、背景を横にずらす量（カメラの向きと、画角と、画面の幅から）も、ここに、純Pythonの関数で置く。
- 判定用の柱の位置（細目の26番）：車の位置と向きから、左前（前へ8 m、左へ3 m）と、右前（前へ8 m、右へ3 m）の位置を、ロジックの座標で返す関数。
- 定義データ：表 `cameras`（1ファイル1表）。項目 `chase`：後方の距離、高さ、注視点までの距離、注視点の高さ、画角（度）、手前、奥。表の定義、実物、壊した場合のテスト、分野の表に足す。
- テスト（`tests/test_camera.py`）：向きが0、π/2、−π/2、πの近くで、目が車の後ろ、注視点が前にあること。向きが増えると、目が、車の右後ろへ回ること（左旋回）。見えるかの判定（真後ろの塊は見えない、奥より遠い塊は見えない、またいでいる塊は見える）。背景をずらす量（向きが1周で、絵が1周ぶん。向きが増えると、絵が右へ流れる）。柱の位置（向き0で、左の柱の z が、車より大きい。向き π/2 で、左の柱の x が、車より小さい。左右の柱は、車の前方の線について、対称）。

### 3. パレットと色の役割（`clipping_point/cp_core/palette.py`、`clipping_point/data/palettes.json`）

- 色の番号の役割を、名で持つ（設計の「描画」の表の32個）。`cp_ui` と `cp_app` は、番号を、ここの名で引く。
- 定義データ：表 `palettes`（1ファイル1表）。項目 `evening`：`colors`（0〜16,777,215 の整数が、ちょうど32個）と、`unshaded`（陰影で暗くしない色の番号の並び。0〜31。灯火の色）。値は、試作の昼の32色に、夕方の式を掛け、空4色と山2色を差し替えたもの。作ったスクリプトを `tools/claude/make_palette.py` に置き（`--check` で、定義データと照らす）、`_notes` に、スクリプトの名を書く。
- テスト（`tests/test_palette.py`）：役割の名が32個で、番号が0〜31を1つずつ。実物のパレットが32色。空の4色が、上から下へ、明るさの順に並ぶ、などの、取り違えを拾う確かめ。

### 4. 車の仮の形の数値

- 車の定義データの寸法（半長、半幅、ホイールベース、トレッド、タイヤの半径）と、仮の形の寸法（全高、車体の箱の上面の高さ、屋根の箱の前後の位置と、横の絞り、最低地上高、タイヤの幅。車の項目の `shape` に出す）から、模型の座標で、箱の頂点と三角形と色の役割を作る。純Python（置き場は、`cp_core` の新しいモジュール。名は、役目が分かるものに）。
- 部品は、車体、屋根、車輪4つ。模型の座標の、面の向きの決まり（上の表）。
- テスト：面の向き（どの箱も、外向き）。寸法（鼻先が +X の端、車輪が、ホイールベースとトレッドの位置）。左右が対称。三角形の数。

### 5. 処理時間の輪（`clipping_point/cp_app/perf.py`）

- 直近の N 回ぶんだけを持つ測り方（更新は120回、実描画は60回。平均と最大。毎秒の回数は、直近の区間の実時間から）。上限のないリストに、ためない。時計は、呼ぶ側が渡す（いまの `PerfMeter` と同じ）。
- 検証の口があるときの `PerfMeter`（全部をためる。煙テストの線の判定に使う）は、そのまま残す。
- 全部をためる測り方（`PerfMeter`）の要約に、平均と最大を足す（細目の29番）。
- テスト（`tests/test_perf.py`）：輪が、古い値を捨てること。平均と最大。回数が0のとき。始まりの時刻が、全部同じとき（区間が0。毎秒の回数は「測れていない」。細目の27番）。
- 表示の桁を超えた値を、桁いっぱいに頭打ちにする関数（`cp_core/flow.py`。細目の27番）と、そのテスト。
- 判定の関数（細目の26番。道具の1つのモジュール。Pyxelに触れない）と、そのテスト：コースの画素と車の画素の下限、空の画素の下限、柱と印の重心の線（左、右、中央の近く）と、画素が0の色、パレットの32色の照らし、矩形の外の違う画素。合っている場合と、合わない場合の両方。

### 6. 3Dの場面と、座標の変換（`clipping_point/cp_app/render.py`）

- 座標の変換の関数（細目の2番。1つだけ）。メッシュ用の数値を、Pyxelの3Dの物にする所（頂点の順の入れ替えを含む）。
- パレットを当てる関数（細目の8番）。色見本の絵（細目の5番）。背景の絵（細目の9番）。
- 場面：根、陰影、カメラ、地面（コースの外の、遠い地面の色の板。コースより、少し低く）、塊ごとのノード、車（根の下に、車体と屋根。車輪は、車の根の下）。
- `cp_app/render.py` は、頭で pyxel を読み込まない（細目の24番）。場面を作る口は、Pyxelを引数で受ける。
- 描く口は、1つ（細目の23番）：描き先の絵、カメラの値、車の位置と向き、描くもの（背景、地面、コース、車、柱と印）を受けて、背景を写し、見えない塊を隠し、根の draw を1回呼ぶ。ふだんの実描画も、判定用の実描画も、巡回の3Dの絵も、この口で描く。
- 判定用の柱と印（やること8）を作る口は、検証の口があるときにだけ呼ぶ。柱と印は、陰影を切った、片面の板（細目の13番）。
- ブラウザ版で、絵の画素をまとめて読む口（`data_ptr()`）が使えるかは、試作の記録に無い。小さく試してから使い、使えなければ、報告に書いて、別の読み方にする。
- Pyxelの3Dの口の使い方は、試作（`spikes/render/common.py`、`world.py`）と、その記録（`spikes/render/RESULT.json`）に従う。記録に無い使い方をするときは、小さく試してから（実測を、報告に書く）。

### 7. アプリと仮の表示

- `cp_app/app.py`：起動時に、パレットを当て、場面を組む。実描画（いまの `render()`。裏画面を消して、描画命令を実行している所）は、細目の10番の順に直す。処理時間の輪を、ふつうの起動でも回す。起動にかかった時間（細目の12番。ブラウザの時計は、`cp_app/web_bridge.py` を通して読む）。頭の注の、描画関数の決めを書き直す。結果を書く所（`finish_run()` と `finish_probe()`）の、画素を数える所は、`pget` の二重の輪をやめて、`data_ptr()` でまとめて読む。
- 巡回の口（`cp_app/tour.py`）：同じパレットを当てる。3Dの絵（細目の14番）。
- 仮の表示（`cp_ui/screens.py`、`cp_ui/fixtures.py`、表示用の値の型 `cp_core/flow.py`）：細目の11番。いまの並び（題、tick と実描画、入力の値の2行、車の値の2行、知らせ）を、上の帯と下の帯に置き直す。処理時間の値は、整数で渡す（0.1 ms刻みの整数、0.1回刻みの整数、0.1秒刻みの整数。描く側で、小数を丸めない。車の値の2行と同じ形）。極端な値（99.9 ms、毎秒999.9回、999.9秒）でも、囲みに収まること。測れていない間（最初の数tick）と、デスクトップ版の `PAGE` の出し方を決める（「-」など）。色は、役割の名で引く。桁の数は、画面の側の定数（区切り9の `SPEED_DIGITS` と同じ形）。
- 画面を足すなら、規則ファイル `ui.md` の決まり（画面の名の一覧、登録、見本データ、テスト）に従う。画面は足さずに、いまの仮の表示を直す形を、推奨とする。
- 置き直しで落ちる、既存のテスト（細目の28番。書き直してよいのは、座標、囲みの大きさ、命令の数）：`tests/test_screens.py`（文字の並びの番号、文字の数、囲みの名と親の並び、車の値の囲みと入力の囲みと知らせの上下、最後の命令、守りのテストの引数の番号）、`tests/test_tour.py`（命令の数）、`tests/test_flow.py`（`PlaceholderView` を、位置の引数で作っている所）、`tests/test_fixtures.py`。

### 8. 判定用の実描画

- 検証の口があるとき（デスクトップ版の、画面なしで回す口と、巡回の口。ブラウザ版の、外から渡す値があるとき）だけ、結果を書く直前に行う。ふつうの起動では、柱も、印も、判定用の絵も、作らない。
- 順（細目の22番、23番、25番）：
  1. 画面と裏画面の、違う画素を数える（`screen_diff`。いままでどおり）。
  2. 裏画面を、いまの世界で描き直す（ふだんの実描画と同じ道）。
  3. 別の絵（裏画面とは別の、同じ大きさの絵）へ、同じ描く口で、次の4枚を描いて、数える。
     - 1枚目：背景と、地面。空の役割の色の画素の数を数える。
     - 2枚目：1枚目と、コース（車は隠す）。1枚目との違う画素の数が、コースの画素。
     - 3枚目：2枚目と、車。2枚目との違う画素の数が、車の画素。裏画面（3Dと2D）と、3枚目の、違う画素を、2Dの描画命令の矩形の内と外に分けて数える。
     - 4枚目：柱と印だけ（背景、地面、コース、車は隠す）。車の左前と右前に、色の違う柱（高さ2 m、幅0.5 m。位置は `cp_core/camera.py` の関数から）。車の模型の右側（模型の座標で、+Z へ1.5 m、高さ1 m）と、鼻先（+X へ3 m、高さ1 m）に、色の違う印。4つとも、陰影を切った、片面の板で、カメラの側（車の後ろ）を向く。色ごとの画素の数と、重心の x を数える。
  4. 柱と印を隠し、コースと車を、見える状態に戻す（例外でも戻す）。
