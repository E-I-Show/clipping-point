## 主が決めた細目

| # | 決めたこと | 理由 |
| --- | --- | --- |
| 1 | 置き場は、設計のモジュールの表のとおり：コースのメッシュ用の数値は `cp_core/track.py`、カメラは `cp_core/camera.py`、Pyxelの3Dに触れる所は `cp_app/render.py`。色の番号の役割は `cp_core/palette.py`（純Python。`cp_ui` と `cp_app` が読む） | 純Pythonの層は、Pyxelに触れない。色の番号は、2Dの画面と3Dの両方が使う |
| 2 | 座標の変換は、設計の式のとおり：ロジックの z の符号を反転して、Pyxelの3Dへ渡す。車の姿勢は `Mat4.from_translation(Vec3(x, y, -z)).rotate_y(degrees(heading))`（段0は、ピッチとロールを掛けない）。カメラの目と注視点も、同じ関数を通す。書くのは `cp_app/render.py` の1つの関数だけ | 設計の「描画」。描画の試作は、向きの決まりが逆（向きが増えると右旋回）で、z を反転していない。試作の車の変換とカメラは、そのままでは写せない |
| 3 | メッシュ用の数値の、面の向きの決まり：`cp_core/track.py` は、ロジックの座標の3つ組を、そのままベクトルとして、(b−a)×(c−a) が外向き（路面と芝は上向き、壁はコースの側向き）になる頂点の順で出す（純Pythonのテストで見る）。座標の変換の関数が、z の反転と一緒に、頂点の順を入れ替える。コースは、裏の面を捨てる設定（`CULL_BACK`）で描く | 設計の「反転に合わせて面の向きも入れ替える」。コースの試作のメッシュは、Pyxelで1度も描かれておらず、描画の試作は、裏の面を捨てずに描いていた。向きが違えば、路面が描かれず、判定（細目の12番）で落ちる |
| 4 | コースのメッシュは、表から作る。約4 mごとに区切り、路面は幅を4つに割る（約3 m×4 mの四角）。部品は、路面、舗装の端の白線（幅0.2 m）、左右の芝、左右の壁（高さ0.9 m）。約60 mごとの塊に分け、塊は、中心と半径を持つ。全周で約3,400三角形。細かい版と粗い版の切り替え、縁石、グラベル、スタート線、高さは、入れない | 設計の「カメラ近くで3 m角以下」に近い大きさで、段1の重さ（画面内3,000〜5,000）に近い所で、処理時間を測る。切り替えは、段1の「コースの描画」 |
| 5 | 色は、試作と同じ出し方：256×256の1枚の絵に、色見本の矩形を並べ、三角形ごとに、矩形の中の1点をUVで指す。模様は入れない（単色） | Pyxelの3Dは、テクスチャを繰り返せず、UVを0〜1に切り詰める（試作の記録）。模様（低コントラストの路面など）は、段1 |
| 6 | 車の見た目は、仮の形：車体の箱、屋根の箱、車輪4つの箱（車の定義データの寸法から作る。数値を作る所は、純Python）。車輪は、車の根の下に置く。影は、入れない | 計画では、車の表示（1台分のモデル）は、段1の「走行画面」。段0は、位置と向きが分かればよい |
| 7 | カメラは、後方追従だけ。車の後方6.2 m、高さ2.1 mから、前方6.0 m、高さ0.9 mを見る。画角58度、手前0.3 m、奥300 m。車の位置と向きに、そのまま付いていく（遅れや、ならしは、入れない）。値は、定義データの表 `cameras` の `chase` に出す。カメラは、ロジックの座標で、目と注視点を返す | 設計の表の値（仮の値）。注視点の高さは、設計に無く、試作の値を置く |
