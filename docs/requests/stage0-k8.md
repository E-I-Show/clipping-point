## やること

### 1. 検査と重ね方（`clipping_point/cp_core/datadefs.py`）

- 規則の部品（細目の2番と3番）。各部品は、値を受けて、問題の文（無ければ `None`）を返す。入れ子の項目は、中の問題に、鍵の道を付けて返す。
- 表の定義：表の名 → ファイルの形（1ファイル1表か、1ファイル1項目か）と、項目の鍵ごとの規則。実物の表の定義（`TABLES`）は、`cars` と `tracks` の2つ（細目の10番）。
- `DataError(problems)`：問題の一覧を持つ例外。文には、件数と、全部の行。
- 読み込み `load_game_data(sources, pack=None, tables=TABLES)`：
  - `sources` は、出荷するデータの「相対の名 → 文」の辞書（例：`{"cars.json": "…", "tracks/test_loop.json": "…"}`）。値が文字列でなければ（読めなかったファイル）、そのファイルの問題。
  - `pack` は、重ねる試験用データ（`(名, 「相対の名 → 文」の辞書)`）。無ければ `None`。
  - 表の定義に無いファイル（知らない名、知らないディレクトリ）は、問題。表のファイルが1つも無い、表が空、も問題。
  - 検査は、知らない鍵、足りない鍵、型、範囲、`id` の重複、無い `id` への参照、ファイルの名と `id` の食い違い。
  - 返すのは `GameData`。問題が1件でもあれば `DataError`。
- `GameData`：表ごとの件数、`ids(表)`（ファイルの順）、`entry(表, id)`（細目の18番。無い `id` は `KeyError`）、警告の一覧、重ねた試験用データの名（無ければ `None`）、保存の名前空間（細目の16番）。
- 問題の行の形：`cars.json:cars[0].name: …`、`tracks/test_loop.json:name: …`。試験用データの中の問題は、頭に `testpacks/<名>/` を付ける。

### 2. ファイルを読む所（`clipping_point/cp_app/data_files.py`）

- pyxel も js もimportしない。ファイルの場所は、このモジュールの場所から引く（`clipping_point/data/`）。
- `read_sources(directory)`：`*.json` と `*/*.json` を読んで、「相対の名（`/` 区切り）→ 文」の辞書を返す。読めなかったファイル（`OSError`、UTF-8でない）は、値を `None` にして返す（問題にするのは `datadefs`）。名は、整列した順で入れる。
- `read_pack(名, 根)`：`testpacks/<名>/` を、同じ形で読む。名の検査（id と同じ字）。置き場が無ければ `ValueError`。
- `load(env, js)`：出荷するデータを読み、デスクトップ版（js が無いとき）で `CP_DATA_PACK` があれば、試験用データを重ねて、`datadefs.load_game_data` を呼ぶ。ブラウザ版は、環境の辞書を読まない。
- ブラウザ版で、同じ場所から読めることを、先に実測する（展開された出荷物の中の `data/`）。

### 3. 実物の定義データと、試験用データ

- `clipping_point/data/cars.json`、`clipping_point/data/tracks/test_loop.json`（細目の10番）。頭の `_notes` に、仮の値の注（車は、型番を付けるかが未定。コースは、段0の縦切り用）。
- `testpacks/extreme/cars.json`、`testpacks/extreme/tracks/<id>.json`（細目の14番）。頭の `_notes` に、試験用データであることと、出荷物に入らないこと。

### 4. アプリ（`clipping_point/cp_app/app.py`）

- `main()` で、保存先を選んだ後に、定義データを読む（細目の17番）。問題があれば、そのまま例外で止まる。
- アプリは、読み込んだ定義（`GameData`）を持つ。設定を読む保存の口の名前空間を、`GameData` の保存の名前空間にする（細目の16番）。保存の往復（`profile.selfcheck`）は、いまのまま。
- 結果に `data` を足す：`{"tables": {"cars": 1, "tracks": 1}, "warnings": 0, "pack": 重ねた名か null, "namespace": 保存の名前空間}`。
- 頭の注に、`CP_DATA_PACK` を足す。
- 世界（`Sim`）へは、まだ渡さない（区切り9）。

### 5. 道具

- `tools/_common.py`：`APP_ENV_PREFIXES` に `CP_DATA` を足す。
- `tools/check.py`：`--only data` を足す。出荷するデータ（警告も問題として数える）と、`testpacks/` の下の各試験用データを重ねたもの。最後の1行に、読めた組の数。1組も調べられなければ2。試験用データは、あるだけ調べる（0個でも、出荷するデータの1組が読めれば0）。

  - `--pack 名` を足す。`CP_DATA_PACK` を渡す。見るもの：上のほかに、置き場に、名前空間 `main` のファイルができていない。指紋は照らさない（最後の1行に `fingerprint=skipped`）。無い名は2。

  - `tracks/` のファイルの名と `id` が違う（`check` が1）
  - `data/` に、表の定義に無いファイルを置く（`check` が1）
  - 試験用データを壊す（`check` が1。`run` は0）
  - 検査が、知らない鍵を見ない（`test` が1）
  - 検査が、最初の1件で止まる（`test` が1）
  - 警告を数えない（`test` が1）
  - 起動時に、定義データを読まない（`run` が1）
  - 重ねる口を読まない（`run --pack` が1）
  - 重ねたのに、保存の名前空間が `main`（`run --pack` が1）
  - 出荷物に `data/` が入らない（`export` が1、`web_smoke` が1）
  - 出荷物に `testpacks` が入る（`export` が1。いまある件があれば、それでよい）

  - 外から入った `CP_DATA_PACK` を、道具が子プロセスへ渡す（`test` が1。守りのテストで見る）
  - 古い結果ファイルが残っている（合格にしない。いまの件の形に合わせる）
- 壊す件とテストの書き方（区切り7のレビューで分かった型）：
  - 期待の語（最後の1行の一部）に、環境で変わる値（Pythonの版、時間、`env=same`）を入れない。
  - 壊す件の test の脚は、狙ったテストに絞る（`-k`）。絞らないと、数字で固定したほかのテストが先に落ちて、狙ったテストが効いているかを見られない。
  - 道具に足した判定の関数（結果の `data` の確かめ、道具が自分で数える所）は、`tests/` にテストを足す（通る場合と、落ちる場合を1つずつ）。
  - 足した壊す件は、単独で回して（`python3 tools/selftest_break.py --only 名前の頭`）、狙った検査の、狙った語で落ちることを確かめる。

## 範囲の外（直さずに報告する）

- 車の走りの値、車の値の矛盾の検査、コースの形と、その検査、データの版を上げ忘れることの見張り（区切り9）。パレット（区切り10）。操作補正、AI、音の表と、MMLの検査（段1から後）。
- 見本データの極端な値を、定義データと試験用データから導くこと、巡回を試験用データつきで回すこと（車名を出す画面ができる段1）。
- 定義データを、世界（`Sim`）へ渡すこと（区切り9）。
- 壊れた保存がある状態からの起動を、実物の保存先で通すこと（段1の、持続の筋書きと一緒）。
- ふるまいの写し（指紋、保存する項目の一覧）は、この区切りでは変わらないはず。変わったら、取り直さずに、報告する。
- `docs/` の文書（言葉の表には、主が「表の定義」「規則の部品」を足してある）と、根のCLAUDE.mdの「規則ファイルの目次」の表のほかの節（「コマンド」の表は、主が直す）。`spikes/` の中。

## 書き方の約束

- 根のCLAUDE.mdの「書き方の約束」と、言葉の表の決めを守る（「定義データ」「試験用データ」「読み込み検査」「データの版」「見本データ」を、混ぜない。「写し」「記録」「枠」「モデル」「段」は、決めた意味のほかに単独で使わない）。
- 出荷するコードに置く仮の値には、`# 仮の値：<根拠>。<合わせる時>` の注を付ける。道具の値は `tools/budgets.json` に出す。
- 新しいパッケージは入れない。テストを通すためだけの特別扱いをしない。落ちるテストを弱めない。

## 報告の形

3. 回した検証（各道具の最後の1行と件数）
4. 回せなかったこと・確かめられなかったこと・範囲の外で直す必要がある所（無ければ「無し」）
5. 推奨の案で決めた細目
6. 「実測して、報告に書くこと」の3点
