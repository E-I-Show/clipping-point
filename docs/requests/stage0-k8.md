## やること

### 1. 検査と重ね方（`clipping_point/cp_core/datadefs.py`）

- 規則の部品（細目の2番と3番）。各部品は、値を受けて、問題の文（無ければ `None`）を返す。入れ子の項目は、中の問題に、鍵の道を付けて返す。
- 表の定義：表の名 → ファイルの形（1ファイル1表か、1ファイル1項目か）と、項目の鍵ごとの規則。実物の表の定義（`TABLES`）は、`cars` と `tracks` の2つ（細目の10番）。
- `DataError(problems)`：問題の一覧を持つ例外。文には、件数と、全部の行。
- 読み込み `load_game_data(sources, pack=None, tables=TABLES)`：
  - `sources` は、出荷するデータの「相対の名 → 文」の辞書（例：`{"cars.json": "…", "tracks/test_loop.json": "…"}`）。値が文字列でなければ（読めなかったファイル）、そのファイルの問題。
  - `pack` は、重ねる試験用データ（`(名, 「相対の名 → 文」の辞書)`）。無ければ `None`。
  - 表の定義に無いファイル（知らない名、知らないディレクトリ、2つの形に当たらない名。細目の22番）は、問題。表のファイルが1つも無い、表が空、も問題。
  - ファイルの頭の形の誤り（細目の21番）は、そのファイルの問題。重ねる前に見て、形の合わないファイルは、重ねない。
  - 検査は、知らない鍵、足りない鍵、型、範囲、`id` の重複、無い `id` への参照、ファイルの名と `id` の食い違い。
  - 返すのは `GameData`。問題が1件でもあれば `DataError`。
- `GameData`：表ごとの件数、`ids(表)`（ファイルの順）、`entry(表, id)`（細目の18番。無い `id` は `KeyError`）、警告の一覧、重ねた試験用データの名（無ければ `None`）、保存の名前空間（細目の16番）。
- 問題の行の形：`cars.json:cars[0].name: …`、`tracks/test_loop.json:name: …`。試験用データの中の問題は、頭に `testpacks/<名>/` を付ける。

### 2. ファイルを読む所（`clipping_point/cp_app/data_files.py`）

- pyxel も js もimportしない。ファイルの場所は、このモジュールの場所から引く（`clipping_point/data/`）。
- `read_sources(directory)`：置き場の下の、全部のファイルを読んで、「相対の名（`/` 区切り）→ 文」の辞書を返す（細目の22番。2つの形に当たらない名も、入れて渡す）。読めなかったファイル（`OSError`、UTF-8でない）は、値を `None` にして返す（問題にするのは `datadefs`）。名は、整列した順で入れる。
- `read_pack(名, 根)`：`testpacks/<名>/` を、同じ形で読む。名の検査（id と同じ字、43字まで）。置き場が無い、または、ファイルが1つも無ければ `ValueError`（細目の15番）。
- `load(env, js)`：出荷するデータを読み、デスクトップ版（js が無いとき）で `CP_DATA_PACK` があれば、試験用データを重ねて、`datadefs.load_game_data` を呼ぶ。ブラウザ版は、環境の辞書を読まない。
- ブラウザ版で、同じ場所から読めることを、先に実測する（展開された出荷物の中の `data/`）。

### 3. 実物の定義データと、試験用データ

- `clipping_point/data/cars.json`、`clipping_point/data/tracks/test_loop.json`（細目の10番）。頭の `_notes` に、仮の値の注（車は、型番を付けるかが未定。コースは、段0の縦切り用）。
- `testpacks/extreme/cars.json`、`testpacks/extreme/tracks/<id>.json`（細目の14番）。頭の `_notes` に、試験用データであることと、出荷物に入らないこと。

### 4. アプリ（`clipping_point/cp_app/app.py`）

- `main()` で、保存先を選んだ後に、定義データを読む（細目の17番）。問題があれば、そのまま例外で止まる。
- アプリは、読み込んだ定義（`GameData`）を持つ。設定を読む保存の口の名前空間を、`GameData` の保存の名前空間にする（細目の16番）。保存の往復（`profile.selfcheck`）は、いまのまま。
- 結果に `data` を足す：`{"tables": {"cars": 1, "tracks": 1}, "warnings": 0, "pack": 重ねた名か null, "namespace": 保存の名前空間}`。`namespace` は、設定を読んだ保存の口（`SaveStore.namespace`）から取る（細目の16番。アプリが、保存の口へ渡し忘れると、ここが `main` になり、道具で落ちる形にする）。
- 頭の注に、`CP_DATA_PACK` を足す。
- 世界（`Sim`）へは、まだ渡さない（区切り9）。
