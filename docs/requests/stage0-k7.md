## やること

### 1. 保存の口（`clipping_point/cp_core/storage.py`）

- 例外：`StorageError`、その子の `CorruptError`（壊れた値）、`StorageFull`（書けない。何も変わっていない）、`NewerVersionError`（新しい形式バージョンの値がある鍵へ書こうとした。何も変わっていない）。
- 鍵の検査 `check_key`：小文字のASCII、数字、`_ . -`。48字まで。外れたら `StorageError`。掛ける相手は、保存の口に渡す鍵。名前空間は、同じ字で、`.` を含まない（別の名前空間の鍵と混ざらない）。退避の鍵（`<鍵>.bad`）は、検査を通さずに作る（48字の鍵も退避できる）。
- 封筒 `wrap(payload, version)` と `unwrap(blob)`（細目の2番）。`unwrap` は `(形式バージョン, 本体)` を返す。`wrap` は、範囲の外の形式バージョンを `StorageError` にする。
- 保存先の決まり：`read(key)`（バイト列か、無ければ `None`）、`write(key, data)`、`delete(key)`（無い鍵でも、黙る）、`keys()`（整列した一覧）。
- `MemoryBackend(capacity=None)`：辞書で持つ。`capacity` を渡すと、合計が上限を超える書き込みを、何も変えずに `StorageFull` にする。
- `SaveStore(backend, namespace="main")`。保存先での鍵は `<名前空間>.<鍵>`。
  - `get(key)`：`(形式バージョン, 本体)` か `None`。壊れていれば `CorruptError`。
  - `put(key, payload, version)`：書く前に、いまある値を見る（細目の22番）。いまある値の形式バージョンが、渡したものより新しければ、書かずに `NewerVersionError`。いまある値が壊れていれば、上書きする。`# 割り切り：` の注を付ける（書くたびに、読みが1回入る。大きい値を入れる段2で見直す）。
  - `quarantine(key)`：保存先から読んだバイト列を、封筒を開けずに、そのまま `<key>.bad` へ写して、元の鍵を消す。退避の書き込みが失敗したら、元の鍵は消さずに `StorageFull`。保存先の読みの例外は、そのまま外へ出す（捕まえるのは `load_settings`）。
  - `delete(key)`、`keys()`、`used_bytes()`。
- 知らせの文（細目の19番）：定数と、その全部の組（例：`NOTICES`）。印字できるASCIIで、仮の表示の囲みに収まる長さ。要るのは、保存先をメモリへ切り替えた、保存が読めないので既定値で動かす、保存が新しい形式バージョンなので保存しない、保存先が読めない、の4つ（文は決めてよい。例：`SAVE DATA UNREADABLE. USING DEFAULTS`）。

### 2. 2つの保存先（`clipping_point/cp_app/storage_file.py`、`clipping_point/cp_app/storage_web.py`）

- `FileBackend(directory)`：1つの鍵を、1つのファイル（`<鍵>.sav`）に持つ。書き込みは、一時ファイルに全部を書く → `flush` → `fsync` を1回 → `os.replace`。`OSError` は、一時ファイルを消して `StorageFull`。読むときの、ファイルが無いほかの `OSError` は `StorageError`。残った一時ファイルは、鍵の一覧に出さない。
- `WebStorageBackend(js)`：`js.localStorage` を使う（細目の5番）。js は引数で受け、このモジュールでは js をimportしない。
  - 書き込みの例外は、容量超過（JavaScriptの例外の名が `QuotaExceededError`）なら `StorageFull`、ほかは `StorageError`。
  - 読んだ値が、base64 として読めなければ、例外にせず、その文字列を符号化したバイト列で返す（細目の5番。符号化でも例外を出さない）。読みの途中のJavaScriptの例外は `StorageError`。
  - `probe()`：試し書き（細目の6番）。返すのは、使える、容量超過、使えない（理由の文つき）の3通り。例外を外へ出さない。
- 保存先を選ぶ関数（`clipping_point/cp_app/storage_select.py`。細目の23番）：ブラウザ版（js を渡したとき）は、`WebStorageBackend` の試し書きの結果で、localStorage かメモリかを決める。デスクトップ版（js が無いとき）は、渡した環境の辞書に `CP_SAVE_DIR` があればファイル、無ければメモリ（細目の7番。相対パスは `ValueError`）。返すのは、保存先、保存先の名（`localstorage`、`file`、`memory`）、知らせの1行（ブラウザ版で、メモリへ切り替えたときだけ。文は `cp_core/storage.py` の定数）。

### 3. 保存する項目（`clipping_point/cp_core/profile.py`）

- `Settings`（書き換えられない dataclass）。項目と既定値（どれも仮の値。注を付ける）：
  - `sfx_volume`、`bgm_volume`：0〜10 の整数。既定は 5
  - `transmission`：`"AT"` か `"MT"`。既定は `"AT"`
  - `assist`：bool。既定は真
  - `view`：`"chase"` か `"bumper"`。既定は `"chase"`
  - `race_serial`：0以上の整数。既定は 0
- 作るときに、型と範囲を検査する。bool を整数の項目に、整数を bool の項目に受けない（`type(...) is` で見る。JSONの `true` と `1` を取り違えない）。
- `SETTINGS_KEY = "settings"`、`SETTINGS_VERSION = 1`、`MIGRATIONS = {}`（細目の10番）、`NOT_SAVED = {}`（`"クラス.項目": "理由"`。細目の11番）。
- 往復の見本 `SELFCHECK_SETTINGS`：全部の項目が、既定値と違う設定。アプリの保存の往復（やること6）と、テストの往復と、道具が使う。
- 保存する項目の一覧を返す関数（例：`schema()`。形式バージョンと、`"クラス.項目": "型の名"` の辞書）。写し（`tests/snapshots/profile_schema.json`）は、これから作る。
- 本体は、JSON（鍵の順をそろえ、空白を入れない。UTF-8）。読むときは、知らない項目、足りない項目、型や範囲の外を、どれも読めない値として扱う（半分だけ読まない）。
- `save_settings(store, settings)`：封筒に入れて `put` する。`StorageError`（子を含む）は、そのまま外へ出す（呼ぶ側が、画面に1行で知らせる。段0で呼ぶのは、検証の往復だけ）。
- `load_settings(store, migrations=MIGRATIONS)`：`StorageError`（子を含む）を外へ出さない（細目の9番）。結果は、値、知らせの1行、書いてよいか。扱いは、次の表のとおり。

| 起きたこと | 値 | 知らせ | 書いてよいか | 保存先に行うこと |
| --- | --- | --- | --- | --- |
| 鍵が無い | 既定値 | 無し | よい | 何もしない |
| いまの形式バージョンで、読めた | 読んだ値 | 無し | よい | 何もしない |
| 古い形式バージョンで、移行が全部通った | 移行した値 | 無し | よい | 何もしない（書き直しは、次の保存で） |
| 新しい形式バージョン | 既定値 | 新しい形式バージョンの文 | よくない | 何もしない |
| 壊れた値（封筒が読めない、本体が読めない、移行の表に無い古い形式バージョン、移行が失敗） | 既定値 | 読めないの文 | よい | `<鍵>.bad` へ退避して、既定値で書き直す。書き直しが失敗しても、結果は変えない（鍵が無い状態と同じ） |
| 壊れた値で、退避が失敗した（`StorageFull` など） | 既定値 | 読めないの文 | よくない | 元の鍵に触れない |
| 保存先の読みが失敗した（`StorageError`） | 既定値 | 保存先が読めないの文 | よくない | 何もしない |

### 5. 指紋（`tools/fingerprint.py`、`tests/snapshots/fingerprint.json`）

- `tools/fingerprint.py`：筋書きの一覧（名、台本、回すtick数、種）、要約の計算（`cp_core` だけを読む。pyxel は読み込まない）、環境の値（Pythonの版と、数学関数の試し値）、2つの写し（細目の15番）の読み書きを持つ。
  - 筋書きは2本：道具の台本（`tools/input_script_smoke.json`）を120 tick回すものと、台本なしで120 tick回すもの。全体の検証の `run` と `run --realtime` が回す形と、同じにする（`run.py` が、どちらの回でも照らせる）。長い筋書きは、車が入る区切り9で足す。

  - `python3 tools/fingerprint.py`：2つの写しと照らす。同じなら0、違えば1（どの筋書きの、どの項目が、何から何へ変わったか。保存する項目の一覧なら、どの項目が変わったか）、写しが無い・読めないなら2。合否は、要約と、保存する項目の一覧だけで決める（細目の14番）。環境の値は、最後の1行に `env=same` か `env=changed` で出す。要約が違い、環境の値も違えば、そのことを先に出す。
  - `python3 tools/fingerprint.py --update`：2つの写しを書き、変わったほうの名を出す。
- `tests/test_fingerprint.py`：写しと同じこと。1 tick多く回すと、要約が変わること。入力を1つ変えると、変わること。種を変えると、流れの状態が変わること。`PYTHONHASHSEED` を `0`、`1`、`12345` にした別プロセスで、要約が同じこと。同じ別プロセスが、文字列の集合（例：`BUTTONS` の名の集合）を回した順も返し、その順が、3通りの間で実際に違うこと（細目の16番）。別プロセスの筋書きは、ボタンを2個押す区間を通るもの（道具の台本）にする。
- 新しく置く2つの写しは、ほかの実装と検証が済んでから、最後に `--update` で書く（途中の値を、何度も書き直さない）。書いた後で値が変わったら、取り直してよい（何が変わったかを、報告に書く）。
