## やること

### 1. 描画命令の層（`clipping_point/cp_ui/canvas.py`、`clipping_point/cp_app/canvas_pyxel.py`）

- 命令を足す：`RectbCommand`（縁だけの矩形。`rectb(x, y, w, h, col)`）、`LineCommand`（線。`line(x1, y1, x2, y2, col)`）。引数の並びは、Pyxelの同名の関数と同じ。座標、大きさ、色は整数に限る（いまの `_require_int` を使う）。
- どの命令も、自分を囲む囲みの番号 `box`（−1 は画面）と、矩形を返す口（左上と、幅、高さ）を持つ。文字の矩形は `text_size()` のインクの箱。線の矩形は、両端を含む外接の矩形。
- `text_size(s)`：細目の5番。`FONT_W = 4`、`FONT_H = 6`。空の文字列は、幅が −1 になる（はみ出しの検査が、空の矩形として数える）。
- `Canvas.box(名, x, y, w, h)`：`with` で使う。`Canvas.boxes` に、名、矩形、親の囲みの番号を並べる。
- `execute(commands, target, ox=0, oy=0)`：足した2つの命令を描く。`ox`、`oy` は、描く位置のずらし（巡回が、余白つきの裏画面へ描くのに使う）。知らない種類は、いまのとおり `ValueError`。

### 2. はみ出しの検査（`clipping_point/cp_ui/check.py`）

- `find_violations(canvas)` が、はみ出しの列を返す（空なら、問題なし）。1件は、種類（`empty`、`off_screen`、`out_of_box`、`bad_char`、`text_overlap`）と、読める文（どの命令か、位置と大きさ）を持つ。
- 判定：
  - `empty`：幅か高さが0以下。この命令は、ほかの判定をしない。
  - `off_screen`：矩形が、画面（`canvas.w`×`canvas.h`）の内に収まっていない。端にちょうど接するのは、内。
  - `out_of_box`：命令か囲みが、親の囲みの内に収まっていない。
  - `bad_char`：文字の命令に、印字できるASCIIと改行のほかの字がある。
  - `text_overlap`：文字の命令どうしの矩形が、重なっている（囲みは問わない）。
- 囲みにも、`empty`、`off_screen`、`out_of_box` を当てる。

### 3. 画面、見本データ、画面の一覧（`cp_ui/screens.py`、`cp_ui/fixtures.py`、`cp_core/flow.py`）

- `cp_core/flow.py`：`SCREEN_NAMES = ("placeholder",)` と、いまの画面の名を持つ最小の型（いまは、いつも `placeholder`）。画面の切り替えは、まだ作らない。仮の表示の、表示用の値の型 `PlaceholderView`（tick、実描画の回数、入力フレーム）も、ここに置く。実描画の回数は、実時間で決まる値なので、表示にだけ使い、世界へ戻さない（注に書く）。いまは `cp_app/app.py` が、この型を組み立てる。
- `cp_ui/screens.py`：仮の表示を、`(canvas, 表示用の値)` を受ける形に直す。`SCREENS = {"placeholder": …}`。仮の表示を、囲みで組む（タイトルの帯、状態の2行、入力の2行）。足す2つの命令を、1つずつ使う（例：入力の2行を、縁だけの矩形で囲む。帯の下に、線を引く）。巡回が、実物のPyxelの画素と照らせるようにするため。
- `cp_ui/fixtures.py`：`VARIANTS = ("typical", "extreme")`、`build(screen, variant)`。知らない画面と変種は `KeyError`。仮の表示の極端な値は、tick と実描画の回数が 9,999,999、舵のアナログ値が −1、アクセルとブレーキが最大、ボタンを10個とも押している。
- `cp_app/app.py`：`flow` の画面の名で `SCREENS` を引いて描く。
- 区切り5で足した、仮の表示への配線の守りのテスト（`tests/test_screens.py` の、`app.py` のソースを読むテスト）は、描き方の形が変わるのに合わせて直す（`update()` が入力フレームを残し、`render()` が、それを表示用の値に入れて、画面へ渡していること）。守りは外さない。壊す件（`test_app_draws_a_neutral_frame_on_the_placeholder`）も、形を合わせる。

### 4. 道具 screen-check（`tools/screen_check.py`）

- Pyxelを使わず、同じプロセスで回す。`[--only 画面の名]`。
- 予定は、`SCREENS` の全部の画面 × 全部の変種。件ごとに、`Canvas` を作り、見本データで画面を組み立て、`find_violations` を当てる。
- 終了コード：はみ出しがあれば1。回り切れなければ2（予定が0件、`--only` の名が無い、画面か見本データが例外を出す、画面が命令を1つも残さない）。回り切って、はみ出しが無ければ0。
- 最後の1行は `_common.finish()` で出す（`screen_check: OK screens=回した件数/予定の件数 violations=N not_checked=N` の形）。はみ出しは、1件ずつ、画面と変種の名を付けて出す。

### 5. 道具 tour（`tools/tour.py`）と、巡回の口（`clipping_point/cp_app/tour.py`）

- 巡回の口（アプリの側）：環境変数 `CP_TOUR=<結果ファイル（JSON）の絶対パス>`、`CP_TOUR_DIR=<画像の置き場の絶対パス>`、`CP_TOUR_ONLY=<画面の名>`（省けば全部）。`CP_TOUR` があれば、画面なしでPyxelを始め、巡回して、結果ファイルを書いて終わる（`pyxel.run` も `pyxel.flip` も呼ばない。`pyxel.quit` は使わず、`sys.exit` で終わる）。`CP_TOUR` と `CP_TOUR_DIR` が絶対パスでなければ、起動時に `ValueError`。`CP_SMOKE` と `CP_TOUR` の両方があれば、起動時に `ValueError`。`tools/_common.py` の `child_env` は、外から入った `CP_TOUR` で始まる名も除く。
  - 画面 × 変種ごとに、見本データで画面を組み立て、次を行う。
    - 全体：余白16ピクセルつきの検査用の裏画面（352×272）へ、(16, 16) ずらして全部の命令を描く。余白に出た画素の数と、画面の内の、背景と違う画素の数を数える。
    - 命令ごと（細目の12番）：全体の絵とは別の、検査用の裏画面を、その命令の色と違う色で消し、その命令だけを描く。矩形の外の画素の数と、矩形の内の画素の数を数える。空白だけの文字の命令は、内の画素が0でよい。
    - はみ出しの検査（`find_violations`）も当てて、結果に入れる。
    - 画像を保存する：全体の絵（全部の命令を描いたもの。命令ごとの照合で描き直した絵ではない）から、画面の大きさ（320×240）を切り出して、2倍で、`<置き場>/<画面の名>_<変種>.png` に。
    - 結果には、画面 × 変種ごとに、命令の数と、照らした命令の数を入れる。
  - 画素を照らす計算は、Pyxelに触れない関数に分けて、テストできる形にする（画素の並びを受けて、数を返す）。Pyxel（のモジュール）は、引数で受ける。
  - 結果ファイルは、全部の画面を回した後にだけ書く（一時ファイルに書いて、差し替える）。
- 道具 `tools/tour.py [--only 画面の名]`：`out/tour/` を消して作り直し、アプリを別プロセスで回す。
  - 回り切れなければ2：予定（全部の画面 × 全部の変種）が0件、アプリの終了コードが0でない、結果ファイルが無い、予定のどれかが結果に無い、画像が無い、画像の大きさが640×480でない、画面が空（背景と違う画素が0）、照らした命令の数が0か、道具が同じ見本データでPyxelなしに組み立てた命令の数と違う、`--only` の名が無い。
  - 問題があれば1：余白に画素がある、命令の矩形の外に画素がある、矩形の内に画素が無い命令がある、はみ出しがある。
  - 最後の1行は `tour: OK shots=回した枚数/予定の枚数 commands=照らした命令の数 problems=N dir=…` の形。
- `tools/verify.py`：`STEPS` に `screen-check` と `tour` を足し、`NOT_YET` から外す。順は、check → test → screen-check → run → run-realtime → tour → export → web-smoke。
- `tools/verify.py` の `AREAS`（計画の「検証の組」の表のとおりに。違えるなら、理由を行の注に書く）：
  - 「画面（2D）」に、足したファイルを並べる。テストの絞りに、新しいテストの語を足す。足す手順の run を残すかを決めて、行の注（「区切り6で見直す」とある所）を直す。
  - `cp_ui/check.py` と `cp_ui/fixtures.py`（と、そのテスト）は、「検証の道具と検査の決まり」にも並べる（計画の表で、はみ出しの検査と見本データは、selftest-break つきの分野）。
  - `cp_core/flow.py`（と、そのテスト）は、分野「カメラと画面の状態」の行を足して並べる（足す手順は、計画の表の run、screen-check）。
- `tools/budgets.json`：足す値があれば、仮の値の注を付ける。

### 6. 壊す件（`tools/selftest_break.py`）

少なくとも次の形。

- 文字を、囲みより長くする（`screen_check` が1）
- 文字を、画面の外に置く（`screen_check` が1）
- 文字に、ASCIIでない字を入れる（`screen_check` が1）
- 極端な値のときだけ、はみ出す（`screen_check` が1。ふつうの値だけなら通ることも、テストで見る）
- 画面が例外を出す（`screen_check` が2）、画面が何も描かない（2）、`--only` の名が無い（2）、変種が0個（2）
- 見本データに無い画面を、`SCREENS` に足す（`test` が1。突き合わせのテスト）
- 文字の幅の計算を小さく間違える（`FONT_W = 3`。`tour` が1。`screen_check` は0のまま通ることも、対照の件として置く）
- 実行の側で、縁だけの矩形を、命令より2ピクセル広く描く（`tour` が1）
- 実行の側で、文字の命令を描かない（`tour` が1。矩形の内に画素が無い）
- 実行の側で、線を、命令と違う位置に描く（`tour` が1）
- 巡回が、画面を1つ飛ばす（`tour` が2）、途中で例外を出す（`tour` が2）、`--only` の名が無い（`tour` が2）、変種が0個（`tour` が2）
- 巡回が、命令ごとの照合を飛ばす（`tour` が2。照らした命令の数が合わない）
- 巡回が、全体の絵でない絵を保存する（余白ごとの大きさ。`tour` が2）
- 古い結果ファイルと画像が残っている（合格にしない）
- 全体の検証の中で、`screen-check` か `tour` が落ちる（`verify --all` が1）

- 「段0 区切り6の巡回で、実際の画素と照らす形に置き換える」と書いてある2か所（`.claude/rules/ui.md` の「テストと道具」と、`tests/test_screens.py` の、配線の守りのテストの注）は、区切り6の後に偽になる（巡回は見本データで描き、守りのテストは残す）。「画面の状態を作る段1で、入力で画面を進める巡回に置き換える」に直す。

## 実測して、報告に書くこと

- `pyxel.Image` の画素を、まとめて読めるか（`data_ptr()`）。読めるなら、1画素ずつ読む形（`pget`）と比べた時間。使う形と、その理由。
- `screen_check.py` と `tour.py` にかかった秒数。命令ごとの照合の、1画面あたりの時間。
- 文字の大きさの式（細目の5番）が、実物の画素と合ったか（合わない字があれば、その字）。
- 保存した画像の大きさ（幅、高さ）と、置き場。
- 保存した画像を、Readで見た枚数と、見ていない枚数。見て気付いたこと（文字が下地に隠れている、重なっている、など。機械の検査は、描く順の誤りを拾わない）。
- `verify.py --all` と `selftest_break.py` にかかった秒数。

## 回す検証

1本ずつ回す：`python3 tools/check.py`、`python3 tools/test.py`、`python3 tools/screen_check.py`、`python3 tools/run.py`、`python3 tools/run.py --realtime`、`python3 tools/tour.py`、`python3 tools/export.py`、`python3 tools/web_smoke.py`、最後に `python3 tools/verify.py --all --selftest`（約11分）。各道具の最後の1行を、そのまま報告に写す。道具の出力をパイプに通して、終了コードを見失わないこと。

## 範囲の外（直さずに報告する）

- 画像の命令（`blt`）。3Dの描画と、走行画面の巡回（区切り10）。画面の状態と切り替え、メニュー、重ねる画面と通知文の、検査対象との突き合わせ（段1 区切り6）。定義データから極端な値を導くことと、文字数の上限（区切り8）。描く順の誤り（文字が、後から描いた下地に隠れる）を、機械で拾うこと（いまは、画像を目で見て拾う）。保存、乱数、指紋（区切り7）。
- ブラウザ版での巡回。
- `docs/` の文書（言葉の表には、主が「囲み」「縁だけの矩形」「インクの箱」「表示用の値」「見本データ」を足してある。設計のモジュールの表には、主が `cp_app` の `tour` を足してある）と、根のCLAUDE.mdの「コマンド」の表（主が直す）。ほかに直す必要があれば、何をどう直すかを報告に書く。

## 書き方の約束

- 根のCLAUDE.mdの「書き方の約束」と、言葉の表の決めを守る（「枠」「写し」「記録」「モデル」は単独で使わない。`Canvas.box` は「囲み」、`rectb` は「縁だけの矩形」）。
- 出荷するコードに置く仮の値には、`# 仮の値：<根拠>。<合わせる時>` の注を付ける。道具の値は `tools/budgets.json` に出す。
- 新しいパッケージは入れない。テストを通すためだけの特別扱いをしない。落ちるテストを弱めない。

## 報告の形

1. 変えたファイル（作ったものは、ディスクにあることを確かめてから書く）
2. 設計と、この文の細目からのずれ・変えた値・新しく足した割り切り
3. 回した検証（各道具の最後の1行と件数）
4. 回せなかったこと・確かめられなかったこと・範囲の外で直す必要がある所（無ければ「無し」）
5. 推奨の案で決めた細目
6. 「実測して、報告に書くこと」の6点
