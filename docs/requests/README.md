# 頼みの文

> 要約：サブエージェントに頼むときの文のひな形と、区切りごとの頼みの文の置き場。区切りの実装を頼んだ文は、`stageN-kM.md` の名で残す。型は `.claude/agents/` の実装役、レビュー役、読み手の3つ。

## 決まり

- 頼みの文には、範囲、設計の節、先に読む規則ファイル、やること、回す検証、範囲の外は直さずに報告すること、を書く。
- 規則ファイルは、差分を見るだけでは読み込まれない。先に読むものとして、名を挙げる。
- 細目は、主のエージェントが決めて書く。実装の途中で合わなければ、実装役が報告に書く。
- 報告は鵜呑みにしない。主が道具を回し直し、採る前に1〜2件を自分で確かめる。
- コミットとpushは、主のエージェントだけが行う。

## 実装役へ（型：implementer）

```
【範囲】段N 区切りM：<名>
【設計】docs/design/<文書> の <節>。docs/plan.md の <段> の区切りMの行
【先に読む規則ファイル】.claude/rules/<分野>.md
【元にする試作】spikes/<領域>/（あれば）
【やること】
- <項目。主が決めた細目を含む>
【回す検証】python3 tools/verify.py --all（道具か検査の決まりに触れたら --selftest）
【範囲の外】直さずに報告する：<後の区切りで作るもの、docs/ の文書、spikes/ の中>
【コミット】しない。gitは status と diff だけ。
```

報告の形は、型に書いてある（変えたファイル、設計からのずれ、回した検証、確かめられなかったこと、決めた細目）。足して聞きたいことがあれば、6番目として書く。

## レビュー役へ（型：reviewer）

区切りのレビューは、1体ずつ頼まずに、ワークフロー（`tools/claude/step_review.js`）で回す。渡すものと読み方は `tools/claude/README.md` にある。

## 読み手へ（型：reader）

```
【領域】<名>
【読む所】<パスの範囲>
【返すもの】入口／値を読む口／テストと道具／関わる定義データと読み込み検査／関わる画面／関わる規則ファイル。読めなかった所があれば書く。
```

## 実装の前に、頼みの文をレビューする

入力フレームや描画命令のように、後の区切りの土台になる形を決める区切りでは、実装役に渡す前に、頼みの文そのものを、型を付けたレビュー（`tools/claude/step_review.js`、1観点、2体）で確かめる。見るのは、設計、計画、正本、いまのコードとの食い違いと、仕組みの穴。結果は `docs/reviews/stageN-kM-request.txt` に置き、通った指摘を頼みの文に反映してから渡す。
