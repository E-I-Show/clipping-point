# 作業の補助（tools/claude/）

> 要約：Claude Codeが作業を進めるためのスクリプト。検証の道具（`tools/` の直下）とは別で、出荷物にも全体の検証にも入らない。gitで管理し、使い方はここに書く。

| ファイル | すること | 使う時 |
| --- | --- | --- |
| `step_review.js` | 区切りの成果を、観点ごとのレビュー役と反証役で見るワークフロー | 区切りの実装と検証の後、コミットの前 |
| `review_summary.py` | レビューの結果をまとめる。未評価があれば1で終わる | レビューの結果が届いた時 |
| `usage_row.py` | 週の使用率を、作業記録の表の1行にし、停止の線を判定する | 区切りごとと、サブエージェントやワークフローを始める前 |
| `handoff_hook.py` | セッションの開始時に、作業の控えを差し込む（`.claude/settings.json` から呼ばれる） | 自動。手では呼ばない |
| `canon_digest.py` | 正本の要約値の写しを見る、取り直す | 取り直しは、採られた改訂案を正本に当てるコミットでだけ |

## 区切りのレビュー

1. 主のエージェントが `python3 tools/verify.py --all` を回し直し、Claudeのモデルと週の使用率を確かめてから、始める。いまの値に見込み（レビュー8体で約6〜10ポイント）を足して95%を超えるなら、始めない。
2. Workflowの道具に、`scriptPath` で `tools/claude/step_review.js` の絶対パスを、`args` に次の形を渡す。

```
{
  "step": "段N 区切りM：<名>",
  "targets": "見るファイルの一覧（変えたファイルは git status --short の出力を写す）。ふるまいの写し（tests/snapshots/）を変えたかどうか。見ないものも書く",
  "basis": "照らす決まりの出どころ（設計の節、計画の節、頼みの文、規則ファイル）",
  "note": "主が回し直した検証の結果。後の区切りで作るもの。実装役が挙げた、確かめられなかったこと",
  "agentType": "reviewer",
  "lenses": [{"key": "fakepass", "title": "見かけの合格", "prompt": "何をどう追うか"}]
}
```

3. 観点は、区切りの中身に合わせて4つ前後を選ぶ。これまで使った観点：見かけの合格、設計・計画との食い違い、層の分離と決定性、テストの穴と揺れやすさ、出荷するコードに入った検証の口の安全さ、再開できるか、言葉の表。詰みが起きうる区切りでは、「詰み」を独立の観点にする。
4. 結果が届いたら、まず週の使用率を読み直す。結果のJSONは、完了の知らせに書いてある出力のファイル（セッションの作業場所の `tasks/<タスクのid>.output`）。`python3 tools/claude/review_summary.py <ファイル> --out docs/reviews/stageN-kM.txt` で読み、同じ文をリポジトリに残す（コンテナが替わると、出力のファイルは消える）。`--case id,id` で起きる場合も、`--rejected` で退けた指摘も、`--notes` で役が書いた「見られなかった所」も出る。
   - 最後の1行の `unevaluated` が0でなければ、その観点を回し直すか、主が自分で見る。指摘0件に数えない。
   - `role_notes` が0でなければ、`--notes` で読み、作業記録の区切りの節に「レビュー役が見られなかった所」として写す。
5. 通った指摘は、主が1〜2件を自分で確かめ直してから、直す（主が直すか、実装役に続けて頼む）。直しの後は、同じ組の検証を回し直す。
6. 作業記録の区切りの節に、体数（観点の数の2倍）、指摘の件数、反証を通った件数、採った件数、未評価を書く。最後の1行は `review_summary: OK lenses=N findings=N passed=N rejected=N unevaluated=N role_notes=N` の形。`--out` のファイルには、引数に関わらず、起きる場合、退けた指摘、役が見られなかった所の全部が入る。

`agentType` は、サブエージェントの型（`.claude/agents/reviewer.md`）が使えるセッションで渡す。レビュー役の型はshellを持たないので、差分ではなく作業ツリーのファイルを読ませる。

## 週の使用率

読み方は `docs/worklog.md` の「週の使用率の推移」にある。読んだ値を渡すと、表の1行と、線の判定が出る。

```bash
python3 tools/claude/usage_row.py --seven-day 0.21 --overage-included 0.12 --resets-at 1794902400 --label "段0 区切り3のレビューの後"
```

## 作業の控えの差し込み

`.claude/settings.json` の SessionStart のフックが `handoff_hook.py` を呼ぶ。新しいセッションでは数行の案内だけ、圧縮、再開、`/clear` の後は控えの全文を出す。確かめるときは、次のように回す。

```bash
echo '{"source":"compact"}' | python3 tools/claude/handoff_hook.py
```
